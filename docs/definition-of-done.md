# UniTrack — Definition of Done (DoD)

Sprint 1 | Team Agreement

## Purpose

This Definition of Done explains when a UniTrack task is
considered complete. All six team members must follow the
same checklist to ensure our work is functional, tested,
reviewed, and ready to demonstrate.

## 1. Definition of Done

A Jira card is considered Done only when:

- [ ] All acceptance criteria in the Jira card are satisfied.
- [ ] The feature or task has been implemented completely.
- [ ] The code has been reviewed by at least one teammate.
- [ ] Relevant tests have been executed successfully.
- [ ] User-facing features have been tested on a real phone.
- [ ] Existing functionality has not been broken.
- [ ] No critical bugs remain unresolved.
- [ ] No passwords, API keys, or private information are committed.
- [ ] The changes have been merged into the main GitHub branch.
- [ ] The implemented work has been demonstrated during the Sprint Review.
- [ ] The Jira card contains relevant evidence and is updated accordingly.

## 2. Testing Checklist

Before marking a card Done, verify:

### Functional Testing
- [ ] The feature works as described in its acceptance criteria.
- [ ] Normal user actions produce the expected results.
- [ ] Invalid inputs and error cases are handled correctly.

### Integration Testing
- [ ] The feature works with the relevant parts of UniTrack.
- [ ] Database operations work correctly, when applicable.
- [ ] Existing features continue working.

### Mobile Testing
- [ ] User-facing pages work on a real phone.
- [ ] Buttons, forms, and navigation are usable.
- [ ] The layout is readable without horizontal scrolling.

### Code and Security
- [ ] A teammate has reviewed the code.
- [ ] Relevant automated tests pass.
- [ ] Private credentials are not exposed.
- [ ] Only authorized users can access restricted functionality.

### GitHub and Jira
- [ ] Changes are committed with a meaningful message.
- [ ] The code is merged into main.
- [ ] The Jira card includes testing evidence or a reference to it.
- [ ] The completed work is shown during the Sprint Review.

For database-only or documentation tasks, non-applicable
UI checks may be marked N/A with an explanation.

## 3. Team Agreement

All six UniTrack team members must review and agree to this
Definition of Done.

The Scrum Master ensures the checklist is accessible and
used consistently.

The Product Owner verifies that the delivered work satisfies
the agreed acceptance criteria.

The entire team is responsible for meeting the Definition of Done.

## 4. Important Rule

A task is not Done simply because someone finished writing
the code.

It must be reviewed, tested, merged, and demonstrated before
the team considers it complete.
